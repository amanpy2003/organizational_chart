# Organizational Chart Generator

Upload an Excel file describing your organization's reporting hierarchy and get a
clean, interactive, exportable org chart — no manual box-drawing.

```
Excel Template → Upload → Validate → Build Hierarchy → Interactive Chart → PDF/PNG/SVG/Excel Export
```

## Architecture

- **`backend/`** — Python + FastAPI. Parses the Excel file, validates the data
  (missing/duplicate IDs, invalid manager references, circular reporting,
  multiple roots), builds the hierarchy tree from `Employee ID` /
  `Reports To Employee ID` only, and renders paginated PDF exports with
  ReportLab (a full server-side re-layout, not a screenshot — so exports of
  very large orgs are never clipped or incomplete). Stateless: each request
  is self-contained, no database required.
- **`frontend/`** — React + TypeScript + Vite. Renders the interactive chart
  with [`@xyflow/react`](https://reactflow.dev) (React Flow) for pan/zoom/
  custom nodes and `dagre` for automatic hierarchical layout, so cards never
  overlap regardless of how many direct reports a manager has. State lives in
  a `zustand` store, cached to `localStorage` so a page refresh doesn't lose
  your chart.

See `backend/README.md` and the inline code for service-level details.

## Quick Start

### 1. Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS/Linux
pip install -r requirements.txt
copy .env.example .env         # or: cp .env.example .env
python scripts/generate_sample_data.py   # generates backend/sample_data/*.xlsx
uvicorn app.main:app --reload --port 8011
```

Backend runs at `http://localhost:8011`, docs at `http://localhost:8011/docs`.

> Picked 8011 (and 5180 for the frontend, below) instead of the more common
> 8000/5173 defaults specifically because those are frequently already taken
> by other local projects — if a port silently falls back to a different one,
> the frontend and backend stop agreeing on where to talk to each other and
> every request fails CORS with a generic "upload failed" error that's hard
> to trace back to "wrong port". If 8011 is ever taken on your machine, pick
> any free port, update `frontend/.env.local`'s `VITE_API_BASE_URL` to match,
> and add it to `backend/.env`'s `CORS_ORIGINS` (any `localhost`/`127.0.0.1`
> port is allowed by default anyway, so this mostly matters for non-local
> deployments).

Run the test suite:

```bash
pytest
```

### 2. Frontend

```bash
cd frontend
npm install
copy .env.example .env         # or: cp .env.example .env
npm run dev
```

Frontend runs at `http://localhost:5180` (pinned in `vite.config.ts` — see the
note above on why).

### 3. Try it

1. Open `http://localhost:5180`.
2. Click **Download Excel Template**, or just upload one of the fixtures in
   `backend/sample_data/` (`valid_small_50.xlsx` is a good first try;
   `valid_large_500.xlsx` exercises the wide-fanout / deep-hierarchy / large-org
   requirements; the `invalid_*.xlsx` files exercise validation error handling).
3. Upload → review the validation summary → **Open Organizational Chart**.
4. Search, filter by department/level, expand/collapse, switch layouts, and
   export to PDF/PNG/SVG/Excel from the toolbar.

## Excel Schema

| Column | Required | Notes |
| --- | --- | --- |
| Employee ID | Yes | Unique. The only field used (with Reports-To) to build the hierarchy. |
| Employee Name | Yes | |
| Designation | No | Descriptive only. |
| Department | No | Descriptive only; drives department color-coding and filtering. |
| Reports To Employee ID | No | Blank for the top-most employee(s). |
| Location | No | |
| Email | No | |
| Level | No | Descriptive only. |
| Employment Type | No | Full-Time / Part-Time / Contract / Intern. |
| Status | No | Active / Inactive / On Leave. |

The hierarchy is built **exclusively** from Employee ID / Reports To Employee
ID — designation, department, name, and level never influence structure.

## Sample & Test Data

Generated by `backend/scripts/generate_sample_data.py` into `backend/sample_data/`:

- `valid_small_50.xlsx` — ~45 employees, multiple departments, a 12-report wide manager.
- `valid_large_500.xlsx` — 500 employees, a deliberately wide manager (35+ direct reports) and a deliberately deep chain (10+ levels).
- `invalid_duplicate_ids.xlsx`, `invalid_missing_ids.xlsx`, `invalid_manager_reference.xlsx`, `invalid_circular_reference.xlsx`, `invalid_multiple_roots.xlsx` — one validation failure mode each.

## Notes on the PDF export

The PDF is not a screenshot. On export, the backend independently re-lays out
the full tree (a subtree-width tree-layout algorithm) and draws every card and
connector with ReportLab. For very large organizations that don't fit on a
single sheet even at A0, it tiles the chart across multiple pages, always
cutting through the empty space between sibling groups or hierarchy levels —
never through a card.

## Future Extensibility

No database is used in v1 — the upload endpoint is stateless and returns the
full normalized tree in one response. The data model (`OrgNode` /
`Employee` schemas) is decoupled from both the Excel parser and the chart
renderer, so adding a persistence layer, multi-organization support, or an
HRMS/API data source later means adding a new service alongside
`excel_service.py`, not rewriting the hierarchy or chart layers.
